The app makes no network call for nutrition. Claude runs on a developer machine and its output is baked into the shipped files. There is no relay, no API key, no runtime fallback — every fetch() in the app points at a local /data file.

Two stages on a build machine, one artefact on the phone.

How a number earns trust

Nothing a model says is used until it survives nutrition-label arithmetic — energy must match its own macros (4·protein + 4·carbs + 9·fat − 2·fibre), and no per-100 g figure may exceed what 100 g can hold. Then three independent readings are compared.

USDA FNDDS

The measured reference: 31 nutrients per food. Authoritative for foods it names cleanly, unreliable for composed or “as-served” dishes it only averages.

Claude Sonnet

Recomputes each dish from a recipe — never shown the USDA number, so agreement is real evidence rather than an echo.

Claude Opus

A second, independent computation that settles the disagreements. Also never shown a prior value.

The deciding rule: a food is corrected when both models miss USDA in the same direction — USDA is the outlier — not merely when the two models happen to match each other. That is what catches a watery survey row (clam chowder at 35 kcal/100 g) that is perfectly self-consistent and still wrong. The 37 hand-checked “golden” foods are never overwritten.

Seven oils, nuts and seeds were also checked digit-for-digit against published values — coconut oil 862, olive oil 884, chia 486, macadamia 718, pine nuts 673, hemp 553, pumpkin seeds 559. All seven match exactly. These are the rows with the largest naive-Atwater gaps, and the gap is correct: fats and fibrous seeds use food-specific energy factors, which is precisely why the tolerance exists.

The offline library

1,744 dishes the USDA set never had, across 26 groups — split by cuisine and by category, because a cuisine prompt returns restaurant dishes and forgets a plain banana, while a category prompt returns staples and forgets regional cooking. Names were deduplicated in code, never by the model.

What it deliberately omits: micronutrients. The library carries energy, macros, fibre, sugar, saturated fat and sodium — the figures a recipe determines. Selenium and vitamin K come from laboratory measurement, not reasoning, and an invented value would be worse than an absent one. USDA foods keep their full measured profile, are excluded from the library, and always outrank it in search.

Reproduce it

Every model reply is cached and committed, so the build itself never calls anything — it stays offline and reproducible.

# harden the measured set
npm run verify:nutrition      # Sonnet vs USDA, blind to the USDA value
npm run adjudicate:nutrition  # Opus settles the disagreements
npm run build:db              # fold in corrections, through every validation gate

# widen the offline coverage
npm run build:catalogue       # what people actually eat; deduped in code
npm run build:library         # cost it out, validate every row, ship the JSON
